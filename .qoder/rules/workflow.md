# 项目工作流规则（workflow）

本项目 `agent_harness`：用 Flutter + Genkit 从零实现的**桌面端 AI Agent 工作台**（chat UI + tool-call 投影 + 分栏 workbench；macOS/Windows/Linux 三桌面目标，见 ADR-0003），设计思想分别取自 dsh（Runtime 内核）与 better-sidebar（工作台交互），不 fork 二者代码。

顶层形态是**两种工作区模式**（ADR-0007 立模式，ADR-0037 换内核）：**企划**（当前工作区内 .md 的本地工作台：一个集合 = Table/List/Gallery/Board/Calendar 对同一份 `PlanStruct` 记录的五种投影，外加 All Content／对象信息／模板／Date／Gallery／回收站几面库屏、主屏组件条与块编辑器）与**代理**（对话 + 工具环 + 双树工作台）。

所有编码任务遵循 `.qoder/rules/ponytail.md` 的懒惰阶梯：先问是否需要构建、是否已有现成实现，再写最少的代码。以下规则在此基础上补充本仓库的实操约定。凡是命中下方关键词，直接加载对应 skill / 工具执行，不再向用户确认。

## 0. 三条硬不变量（动手前先确认没踩）

| 不变量 | 为什么 | 验证命令（应无输出，注释文字除外） |
| --- | --- | --- |
| Genkit 只活在 `lib/genkit/` | genkit 全系是 0.x 包，破坏性变更应当只砸两个文件，而不是穿过整棵 widget 树 | `grep -rn "package:genkit" lib/ \| grep -v "^lib/genkit/"` |
| 状态模型不碰框架 | `lib/model/` 是运行时与 UI 之间的唯一词汇表 | `grep -rln "package:flutter" lib/model/` |
| 控制器不反向依赖界面 | `lib/state/` 原则上不 import `lib/ui/` | `grep -rn "\.\./ui/" lib/state/` |

第四条边界（ADR-0015，不算"硬不变量"但同样由门禁拦）：`lib/genkit/` 不 import `package:flutter*`、也不 import `lib/state/`——`grep -rn "package:flutter\|\.\./state/" lib/genkit/` 必须为空。它保证的是 `dart run spike/runtime_smoke.dart` 还能编译：那条链曾经经 `state/fs_revision.dart`（一个 `ValueNotifier`）摸到 `dart:ui`，把工具改动的验收门静默弄断了。需要跨层共享的东西若是给 runtime 用的，就放 `lib/model/` 并保持纯 Dart。

第三条的**唯一已知例外**：`lib/state/layout_controller.dart:13` import `ui/layout/columns.dart`（列宽求解要读约束表达式）。要新增例外，先按 §7 立 ADR。

第一条还有一个人工放行例外：`test/restore_projection_test.dart` 是全仓库唯一在 `lib/genkit/` 之外 import `package:genkit` 的测试文件（它要构造持久化形状）。这个例外是刻意的，别"顺手清理"掉。

这三条 grep 现在是**可执行门禁**（ADR-0011，第 6 条由 ADR-0015 补，第 7 条由 ADR-0020 补）：`dart tool/check_architecture.dart` 七条规则（三条不变量 + `lib/genkit/` 既不 import `package:flutter` 也不 import `lib/state/` + `lib/ui` 不直接 `dart:io` + riverpod 只在 `main.dart`/`app_providers.dart` + 反馈条只有一个入口）按**指纹 baseline + 只拦新增**运作，`tool/architecture_baseline.json` 是今日实况而非豁免清单——债务修掉了要 `--update` 把 baseline 缩小。`test/architecture_check_test.dart` 调同一段代码，所以 `flutter test`（= CI）已经在跑它，**不必往 `.github/workflows/` 里加步骤**。

## 2. skill 集合的边界（已按本仓库裁剪）

两份镜像 `.qoder/skills/` 与 `.trae/skills/` 各 **25 个** skill，逐文件一致。曾装过 32 个，以下 **7 个因为"命中即破坏现状"已经移除**（不是禁用，是磁盘上没有了；要恢复必须先满足最后一列前提）：

| 已移除 | 为什么在本仓库有害 | 要用回来的前提 |
| --- | --- | --- |

## 3. 本仓库特有工作流（skill 覆盖不到的部分）

**genkit 升版。** 投影逻辑的依据全写在 `spike/agent_spike.dart` 头部的 FINDINGS（可执行证据）。升完依赖先 `dart run spike/agent_spike.dart` 重跑，再对照这三条：`Part` 是单一 json-backed 类型（`part is TextPart` 永不成立，要用 `PartExtension` 的 `isText`/`isToolRequest`/… 判别）；`SchemanticType.jsonSchema(...)` 不存在，运行时 schema 用 `SchemanticType.from<T>(jsonSchema: ..., parse: ...)`；`chunk.accumulatedText` 是 **turn-global**，不能当单条消息正文，要按 `chunk.raw.modelChunk.index` 分组。若升版使 FINDINGS 失效，先补 ADR 记录新事实，再改 `lib/genkit/`。

**工作区指令注入（ADR-0009）。** `lib/genkit/instructions.dart` 会在开会话或换工作区时，把用户级 `~/.agent_harness/AGENTS.md` 与**从文件系统根到工作区这条链上**的 `AGENTS.md`/`.agents/AGENTS.md` 合成一个块，作为**首条用户消息的前置 TextPart** 发给模型（不是 system prompt——agent 只定义一次、workspace 是活 setter）。三条实操后果：① 本仓库的 `AGENTS.md` 与它指向的规则**现在是模型的输入**，写它就等于写给 agent 的指令，密钥/内部主机名一律不要放进去；② 只向上找、**不向下扫子目录**，子项目的 `AGENTS.md` 要靠 `read` 工具自己取；③ 预算是单文件 8 KiB / 总 24 KiB，超限会**在块里明说截断**，所以别指望长文件后半段生效。`openSession()` 恢复的会话不会重发（历史里已有）。改这块行为的回归面：`test/instructions_test.dart`。

**加/改一个 agent 工具。** 顺序是：`lib/genkit/tools.dart`（`WorkspaceTools` 只注册一次，工具在调用时读 workspace，换文件夹不重注册）→ 需要新事件形状时在 `lib/model/turn_event.dart` / `conversation.dart` 里表达 → `lib/genkit/agent_runtime.dart` 做投影 → UI 侧 `lib/ui/tool/tool_card.dart`。会写文件/执行命令的工具要走 `lib/model/approval_mode.dart` 的审批回路（interrupt → resume），判定见下一段。工具的 description 与返回给模型的 error 文本**不进 i18n**：那是模型读的，不是 UI 文案。验收：`dart run spike/runtime_smoke.dart`（离线跑 no-key / 空 store 路径；带 `DEEPSEEK_API_KEY` 则真跑一轮流式 + 工具环 + 审批 + **覆盖写镜像断言** + 恢复；判成败别看接了管道的退出码）。这道门能不能跑取决于 `lib/genkit/` 保持无 Flutter（ADR-0015，规则 6 守着）——工具需要跨层共享的状态时，把纯 Dart 的形状放进 `lib/model/`，别去 import `lib/state/`。

**审批门禁只有一个顺序（ADR-0012）。** `lib/genkit/tools.dart` 的顶层函数 `decideGate({mode, subject, decided, modeRefusal})`：`plan` 先拒 → 命中 deny 规则带理由拒 → 命中 allow 规则静默放行 → 非 `ask` 放行 → 否则 interrupt。三个可写工具调 `WorkspaceTools.gateFor(kind, subject)`，MCP 外部工具在 `agent_runtime.dart` 的 `_ToolGate` 里调同一个函数——**不要在新工具里自己拼 `shouldInterrupt`**，否则外部/内部会出现两套免问语义。两件事必须同时记住：① 工具"是否只读"的唯一声明是 `WorkspaceTools.readOnlyToolNames`，委托目标（sub-agent）的工具集由它派生，加只读工具就把它加进这个集合，不要再在 `agent_runtime.dart` 里补一份列表；② 规则的 subject **必须与审批面板显示的那串一致**（文件用 `ws.relative(path)`、命令用原文、外部工具用 `server/tool`），由 `ApprovalRequest.ruleFor()` 从 interrupt payload 反推——"记住的东西"和"用户批准的东西"分叉就是安全漏洞。规则落在 `<support>/approvals.json`，按工作区分键；设置页 `approvals` 节可逐条移除（"只能加不能减的免问"按隐藏后门处理）。会话级作用域与 deny 规则的面板入口是**已知缺口**，理由记在 ADR-0012。回归面：`test/tool_gate_test.dart`、`approval_rule_test.dart`、`approval_rule_store_test.dart`、`approval_panel_test.dart`。

**忙时输入只有一个出口（ADR-0013）。** 一次 run 期间用户仍然能提交，去向由 `InputDelivery` 决定：`queue` 排在本轮之后，`guide` 交进本轮。三条不可拆开的事实：① **队列归控制器**（`lib/state/conversation_controller.dart` 的 `_queue`），排空点**只有一个**——`await _consume(...)` 返回之后的那一次 `_drain()`（`send` 与 `respondToApproval` 两条路径都走到）；绝不在 `_handle(TurnFinished)` 里排空，那时旧 subscription 还没 settle，新流会丢掉通知。② **交接归运行时**：`AgentRuntime.guide()` 只在 `_turn != null || _pendingInterrupts.isNotEmpty` 时收下（审批暂停也算在跑），文本由 `_GuideInjector` 这条 `GenerateMiddleware.model` 在**下一次模型调用**写进 `ModelRequest.messages`——追加到最后一条 user/tool 消息，不新开一条（provider 一条 Message 就是一个 turn，避免相邻同角色）。③ **没读走的一定要回来**：`takeUndeliveredGuides()` 在 `_drain()` 开头整批插回队首；纯长回答不会再有模型调用，漏了这一步就是静默丢用户输入。另两条实操后果：`stop()` 只是**停车**（`_queueHeld`），用户再次 send 才放行且新消息先发；队列**刻意不持久化**（它是草稿不是历史，换会话随 `_reset()` 一起丢）。改这块的回归面：`test/input_queue_test.dart`、`test/input_queue_panel_test.dart`，以及 `spike/agent_spike.dart` 的 probe G + FINDINGS 15（genkit 升版必查：若循环不再从被改过的请求派生下一轮，`guide` 会退化成一次性耳语）。

**抄参考实现之前先问它有没有消费者（ADR-0041）。** 参考实现有那棵目录，不等于它有那个功能。对 `ZCode-main` 代码侧逐棵走查，三格"看起来该抄"的东西 grep 消费者都是 0：树内的重命名/新建（`packages/ui/src/workspace-file-tree/` 里 `rename|newFile|createFolder|mkdir` 命中 0）、git 面板的 `unstagePaths`/`discardPaths`（词条在 `packages/ui/src/i18n/locales/en-US.ts:1171-1174`，动作没有 UI 调用点）、diff 的 `selectedLines`（`packages/ui/src/components/ui/diff-viewer.tsx:43,46-50` 有入参、无处理器，`DIFF_VIEWER_UNSAFE_CSS` 是喂给自己的死旋钮）。同一次走查也量到**这里更厚的一面**：git 变更行能逐文件 stage/unstage/discard，`editor_tab` 能改能存（上游的 `PreviewPane` 是纯只读查看器，`writeFile|save|editable|Monaco` 命中 0），树头有搜索（上游侧栏那把才是死键）——所以"上游有"既不是"上游能用"，也不是"我们缺"。三条判据：① 搬一格之前先给它找**调用点**（grep 那个函数名，不是那个 i18n 键）；② 落这里之前先问**有没有等价答案**（终端复制粘贴由 `xterm-4.0.0` 的键位供着，再加一棵右键菜单就是同一件事两种说法）；③ **没人走的动词不许再堆一层**——`WorkbenchController.reveal` 有两条单测而生产零调用点，它缺的不是实现是一格入口，且接进来时必须与 `openFolder` 成对：只展开一棵没开着的树，就是"按下去什么都不发生"的假开关（ADR-0022 那条律长在菜单行上的形态）。顺带两条：`reveal` 只算"展开祖先"，上游那套 transient highlight 本仓库有意没搬（`sidebar_state.dart:27-29`），所以文案说"展开"不说"选中"；跨平台的动作名不许对单一平台承诺（`在访达中显示` → `在文件管理器中显示`，Linux 上只打开所在目录这件事写在 `host/reveal.dart` 的注释里）。回归面：`test/git_tab_test.dart`（两棵，含"树被关掉时那格不出现"，反向验过）、`test/workbench_ui_test.dart`、`test/editor_tab_test.dart`。

**一次 `git status` 只有一个持有者（ADR-0043）。** `lib/state/git_status_store.dart` 的 `GitStatusStore` 是全仓库唯一跑 `git status` 的地方，五个动词各有分工：`read(root, {force})` 是唯一会 spawn 进程的，`reading(root)`/`isFresh(root)` 只读缓存，`invalidate(root)` 是**任何改了工作树之后必须调的一下**（stage/commit/discard/checkout，以及 agent 写文件那条 `fsRevision` 路径），`errorFor(root)` 只有主动索取状态的那个表面才读（文件树从不读它——它没要求过 git 说话，所以不弹提示）。三条实操后果：① **间隔只有一个数**（`GitStatusStore.freshness` = 2s）：面板的 `Timer.periodic` 取它，任何 tab 都不许再写一个字面秒数（ADR-0023 那条时序律在 git 侧的实例），且**只有当那棵 tab 是可见的时才轮**；② 服务递到手里**还是已有的那道 `GitHost` 缝**（`git_tab.dart` 的 `InheritedWidget`，由 `workbench.dart`/`free_window_layer.dart` 供），新读者用 `GitHost.statusOf(context)`，不新建第二道缝，更不在 widget 里自己 `openRepo(...).status()`；③ `Workbench` 与 `FreeWindowLayer` 的 `status` 是**必填**，测试宿主传 `FakeGit.inert()`——给它一个默认值就等于构造一个真 runner，于是每条 widget 测试都真去 spawn 一次 git，而那 30s 进程超时计时器以"A Timer is still pending"弄红十条与 git 无关的测试（与 `plan_workspace_test` 的 FakeAsync 挂死同族：**失败理由和被测的东西毫无关系**）。XY 字母词汇（`badgeOf`/`isStagedEntry`/`isUnstagedEntry`/`isUntracked`）住在 `lib/host/git.dart`，因为它们是 `GitStatusEntry` 的性质而不是某棵视图的词汇（曾住 `git_tab.dart`；那句话只在"只有一个读者"时成立，第二个读者一到就是 ADR-0035 那条律的反面）。画法可以不同而答案必须同一份：git 面板是带底方框（变更就是那一行的主题），文件树是 11px 页边注 + 目录聚合点（那一行的主题仍是文件），头部的"只看变更"只在有变更时出现，并把 `_matchingRows` 的谓词从"名字匹配"换成"在变更集里"（同一棵过滤树，不另写第二棵）。`GitStatusResult.root` 是这条链的必需项：porcelain 的路径相对**仓库顶层**，而树可以 rooted 在顶层之下任意处，没有这个字段第二读者就得自己再跑一次 `rev-parse`。回归面：`test/git_status_store_test.dart`（七棵）、`workbench_ui_test.dart` 的 `a dirty file wears its letter…`（**反向验过**：徽标写死 `null` 即红）与 `no repository means no letters and no filter switch`、`git_tab_test.dart` 那几棵（面板改读 store 之后行为不许变）。

**文案。** 新增或修改 UI 字符串必须**同时**进 `lib/l10n/locales.dart` 的 `enStrings` 与 `zhStrings`，键完全一致（**不记死条数**——它随加键漂移，是典型的会腐烂的断言；对齐才是不变量，现由 `test/l10n_parity_test.dart` 断言两个方向的键集差集为空，ADR-0008）。en 是先写的源语言，zh 逐键回退到 en（`translate()`：`zhStrings[key] ?? enStrings[key] ?? key`），两边都缺则把键本身渲染出来，好让缺口可见。取值走 `context.tr(key, params)`，`{name}` 占位符插值。**守卫只管键不管值**：zh 是否真的翻译过、译得对不对，仍是人眼的事；`{name}` 占位符名两侧是否一致也没进守卫（要加就再立 TST 类 ADR）。**不挂 `AppLocaleScope` 即退化成英文**，这是 widget 测试不关心 i18n 的前提，别改这个 fallback。不做 i18n 的两类内容：持久化进 layout 的 tab 标题（数据不能随语言翻），以及单例 tab 的显示名（在渲染时由类型派生）。

**主题。** 颜色/字号/动效/阴影只从 `lib/theme/dsw_*` 取：别名令牌在 `dsw_alias.dart`，绑定与 elevation ramp 在 `dsw_theme.dart`，排版在 `dsw_typography.dart`，shad 桥在 `dsw_shad_bridge.dart`（DswAlias → ShadColorScheme，反向取 shad 配色即违规）。新增令牌加在 alias 层，让 widget 通过 `context` 拿。抄 dsh 的 CSS 阴影值必须换算——CSS blur 与 `BoxShadow.blurRadius` 不是一回事（见 `DswShadow._blur`）。**对比度是 ADR-0004 的显式豁免面**：动正文级颜色前先 `dart tool/contrast_check.dart`（确定性三求值，只依赖 dart:io/dart:math）并保证 `test/theme_contrast_test.dart` 仍绿；该 ADR 采纳的是"方案 B 显式豁免"，所以低于 AA 的令牌是**决策**而不是待修 bug，别顺手"提亮"。圆角/间距/控件尺寸是 ADR-0017 的面：只在 `lib/theme/dsw_shape.dart` 加档位，`test/theme_token_test.dart` 会扫 `lib/ui/**` 里括号后不是 `DswShape.` 的 `Radius.circular(`（**只认数字的正则拦不住 `wide ? 12 : 999`**，这条改过一回）。

**行里的自由文本必须有 flex 上界。** 侧栏行、工具卡头、状态条这类"一行装一个可变长度字符串"的地方，`Text` 要么是 `Expanded`/`Flexible` 的子件，要么就会溢出面板——**`overflow: TextOverflow.ellipsis` 单独写没有用**，因为 Row 的非 flex 子件是按无限宽量出来的，ellipsis 根本没有触发机会。已踩实过的三处：`composer.dart` 的工作区状态条（长文件夹名撑出 487px）、`diff_tab.dart` 的 `← 旧路径`（ellipsis 在场仍漏）、`primitives/disclosure_row.dart` 的标题（每条工具卡与推理行共用）。守卫是 `test/disclosure_row_test.dart`，它把机制反向验死：同样的 Text 换成非 flex 包装，180px 面板溢出 1224px。窄屏降级也有一条律：**先丢标签与描边，最后才丢座位**（一个控件消失了就不叫降级，叫缺控件）。

**成组靠同一中心线和一个间距，不靠嵌套。** 想让几个控件读成一组，就把它们做成同级、等高、相邻；**把一个控件塞进另一个控件的 `DswHoverTap`/`_Pressable` 里**不是成组，是嵌套：hover 小的会点亮整行、点空白处会触发那个"看起来不相干"的目标、语义树变成"按钮里装按钮"。侧栏底部那枚"孤立的设置按钮"真因就是这个（`005b76c`，守卫 `sidebar_test.dart` 的 `the footer controls are neighbours, not nested targets`——反向验过：旧结构量到触发区右边界 268 > 齿轮左边界 206）。

**"未居中"这类主张只有同轴这一种证法。** 眼睛在截图上量不出一列正中没有偏：把 `ConversationRoot` 在固定视口宽度（1400/1152/700）各起一次，取**输入卡、正文左沿、用户气泡右沿**三块矩形，断言轴差而不是像素——正文左沿 = 卡左沿 + `composerCardWidthInset/2`、气泡右沿 = 卡右沿 − 同一枚 inset、卡中心 = 视口宽度的一半。审计 §3-C 的"正文中心偏右约 66px"就是这样被撤回的：中列一直与卡片同轴，左边那条空白是用户气泡按 dsh 的 `max-width: min(525px, 82%)` **自己**封顶并右对齐的结果（`ui/conversation/message_item.dart:47-60`），不是布局缺陷。**先问"这块本来该不该贴右"，再立缺陷**——旁白与正文在同一列里读起来就是两种对齐。反向验过：`Center` → `Alignment.centerLeft` 即红（`Expected: <326.0> Actual: <32.0>`）。守卫 `chat_view_test.dart` 的 `the transcript and the aside share the card's two axes`（`3990b0c`）。**审计 §U3 是这条律第二次拦住一个尚未立成的缺陷**（2026-09-30 四张真窗截图）："对话列底部三条信息各用一条轴"复核后是**一条轴两种对齐**——统计行居中在内容轴上、工作区状态条是 `Row` 撑满同列所以它的左沿就是卡片左沿，而居中与左对齐是内容语义（会话计数 vs 可点击的工作区入口）不是分叉；撤回记录在 ADR-0034 的"明确不做"里。

**一个状态一枚 token，容器也一样。** 交互态各要一档：hover 与 selected 不许同色（ADR-0017 S2 的 `interactiveSelected`），**一张卡片也不许只有一枚静态边**——输入卡就因此被记成"边界不清"（UI 审计条 4）：屏幕上没有任何东西说明键盘在谁那里。输入卡现在答**两态**：静置 `borderL2DarkmodeThin`(0.06) → hover `borderL3`(0.12，正好 2×)，`AnimatedContainer` + `DswMotion.fast`（那一档动效本来就是 hover/press 反馈）并经 `DswMotion.respecting` 尊重 reduced-motion。**聚焦不再改变描边颜色（ADR-0038，2026-10-01）**：`b9684f4` 曾照 ZCode `ChatPromptEditor.tsx:347` 补出第三态 focus-within `brandPrimary`，真机走查判它是噪音——光标已经在说"键盘在这里"，暗色档下那道 brandPrimary 读起来像一条黑边；于是 composer 收成两态，桥的 `inputTheme` 让 `focusedBorder` 与 `border` 同为 `borderL2`（全仓 `ShadInput` 聚焦都不换边），`dswBareInput` 聚焦也不出现边框。守卫随之**反向改写**为 `composer_test.dart` 的 `the card keeps its stroke when the keyboard lands`：断言聚焦态与静置态**逐像素相同**，hover 仍亮一档，读的仍是**画出来的** `BoxDecoration.border` 而不是 widget 参数——反向验过：换回一枚静置边即红。两件事没被推翻：**hover 与 selected 不同色**那条管的是选中态，不是键盘焦点态；"说话的是边不是底"仍然成立（ZCode 那一步还换 `bg-input-focused`，这里照旧拒绝，免得为一个观感多出两枚随明暗变的字段）。**先复用别名层已有档位，别为一种状态造一枚新令牌**；真要给键盘焦点做指示，按 ADR-0038 的出口是加一枚 2px ring 而不是替换描边，并且重新立 ADR。

**一行高的座位，高度取自字号而不是钉死的像素（ADR-0017 S3）。** 文本缩放现在有真值：`AppFontSize.scale`（0.9/**1.0**/1.15）在 `main.dart` 的 `MaterialApp.builder` 里**乘进**平台自己的 scaler（`MediaQuery.textScalerOf(context).scale(1) * doc.fontSize.scale`），所以 macOS「放大文本」与用户那一档合成而不是互相覆盖，而默认档必须等于 1.0——一个说不清来源的全局缩放会先出现在截图里、再由人猜。**别动 root font-size、别动 `DswType` 的 ramp**：框架的 `textScaler` 已经乘进每一个 `Text`，再造一条 base scalar 就是两处真值。接上步子之后 chrome 会**安静地裁字**（被约束裁掉不报错，只有 `RenderParagraph.getMaxIntrinsicHeight(width)` 与它拿到的 box 高度一比才现形），1.8x 下实测 7 处：共享表头 43.0/24.0（含同行的路径摘要，它就在这表头自己的 `ClipRect` 后面）、进行中行 40.0/26.0、侧栏 New Session 40.0/34.0、模式 chip 25.0/22.0、审批三键 40.0/36.0 与队列 chip 32.0/28.0。律是 `height: <设计像素> * MediaQuery.textScalerOf(context).scale(1)`（1.0 下逐位等于原值，`disclosure_row_test` 钉的 24 就是"零漂移"的证明；shad 的 `ShadButton(height:)` 同时写进 `ConstrainedBox` 的 min **和** max，见 `button.dart:1130-1143`，所以它是钉不是地板）。**`minHeight` 地板对"一行"是错的方向，对"自有两行"是对的方向，这条要记住**：共享表头的 `collapsed` 槽收的是外部任意 widget，行高一旦不设上限它就折成四行、把整行撑到 88px——这种座位的"就一行"本来就是语义（摘要要裁剪，不是把行撑高）。反过来，一个装**它自己两行文字**的行（企划便签行：文件名 + 目录）就该用地板：把 34 的钉高乘上步子，2.2x 下仍报 `overflowed by 0.200 pixels`，因为缩放后的行高**向上取整**（34×2.2=74.8，两行实际 75.0）。判别式是"这格的内容由谁决定"。横向相反：内容该缩短的（New Session 标签、设置页 provider 名）用 `Flexible` 让 ellipsis 有机会触发，该换行的（审批三键）用 `Wrap`；处置由"这个控件的内容能不能多占一格"决定，不由症状决定。**还有一条只在量得出来时才看得见**：`RenderFlex` 给非 flex **一处时序只有一处真值，chrome 也一样（ADR-0023）。** `Tooltip` 是 ADR-0020 之后 `lib/ui` 里最后一枚 Material 交互原语，配色早已走 `DswAlias`（`dsw_theme.dart` 的 `tooltipTheme`），**坏在时序**：30 枚 `Tooltip` 里 19 枚自己写 `waitDuration`（15×500ms、4×600ms），11 枚不写——而 Material 的兜底是 `Duration.zero`（`tooltip.dart:394`，取值顺序 `widget ?? tooltipTheme ?? default` 在 `:542`），本仓库的 `tooltipTheme` 当时又只给了配色，于是那 11 枚**一碰就弹**，且它们恰好全在鼠标横着扫的表面上（tab 条／文件树行／git·diff 行／编辑器图标行／队列条／详情栏头部）。实操三条：① 延迟只允许住在 `lib/theme/`——`DswMotion.tooltipDelay` 经 `tooltipTheme.waitDuration` 带给整个应用，**`lib/ui` 里出现 `waitDuration` 就红**（守卫 `test/tooltip_timing_test.dart`；这是"一个数字出现在两处就是两份真值"那条律在时序上的实例，与 ADR-0014/0022 同族）。② 这枚延迟**故意不进** `DswMotion.respecting()`：它不是动画，reduced-motion 把它归零恰好恢复投诉，理由写在那枚常量的注释里挡住下一个"顺手统一"。③ **widget 测试量不出 hover 时序**——合成指针不启动 `Tooltip` 的计时器，"400ms 时还不该出现"这种断言永远为真（实测逐步计数 `after startGesture: 0 / after 1 frame: 0 / after 400ms: 0 / after settle: 1`，把主题的延迟删光也照样绿）。所以这一类"什么时候出现"的守卫只能写成结构断言 + SDK 取值顺序引用，观感归真机走查；**别补一条看起来像行为验证的空测试**。**同一把尺子还量到了过渡时长（S2）**：`lib/ui` 的 13 处 `Animated*` 里 9 处取 `DswMotion.respecting(context, DswMotion.fast)`、2 处取调用方传入的参数，而 `sidebar.dart:951/989` 那两枚 hover 底色自己写了 `Duration(milliseconds: 50)`——同一个交互比全应用快一倍，且**绕过 `respecting()` 就不尊重"减少动态效果"**。守卫在 `theme_token_test.dart` 的 `motion ramp` 一节：从每个 `Animated*` 的开句往后找它自己的 `duration:`，必须是 `DswMotion.…` 或 `duration: duration,`；**不看 `AnimationController` 的 `duration:`**（那是循环周期：微光 1800ms、行扫过 2600ms、"已复制"回位 1000ms，钉到 100/200/300 的 ramp 上是错的）。所以：新加过渡动画就取 `DswMotion.fast/normal/slow` 并经 `respecting()`，别在界面里写毫秒数。改这块的回归面：`test/tooltip_timing_test.dart`、`theme_token_test.dart` 的 `motion ramp`。

**图标按钮只有一个原语（ADR-0024）。** ADR-0021 收的是点击**机制**，它上面那一层当时没管，于是 `lib/ui` 里长出四枚私有图标按钮，身体逐字相同（`Tooltip` → `DswHoverTap` → 悬停底色），却在半径、形状、色阶、禁用的说法上各答一遍。现在图标控件只认 `lib/ui/primitives/icon_button.dart` 的 `DswIconButton`，六件事由它一处决定：① tooltip **同时就是**语义名（`semanticLabel: tooltip` + `excludeSemantics`，所以不可能出现"写的和念的两套"）；② 底色只 `interactiveBgHover`；③ 时长走 `DswMotion.respecting(context, DswMotion.fast)`（ADR-0023 S2 那条 ramp 的第三枚实例）；④ 半径按盒子尺寸由 `DswShape` 的嵌套律推（≤20→`inset`、≤`controlMd`→`inner`、更大→`control`）；⑤ 色阶静止 `labelSecondary` → 激活（hover **或键盘焦点**）`labelPrimary`、禁用 `labelCaption`；⑥ **选中态只有一个说法**：`selected: true` 一次改三样——底色取 `interactiveSelected`（与 hover 不同档，ADR-0017 S2 那枚）、字形升到 `labelPrimary`、并写进 `Semantics(selected:)`。第一枚用它的是文件树的"只看变更"（ADR-0043）：**一枚看不出开没开的开关与一枚按下去什么都不做的控件是同一类缺陷**（ADR-0022 那条律的形状版），所以别再在调用点手搓底色。**禁用只有一个写法：`onTap == null`**——不要再加 `enabled` 字段：`browser_tab` 曾同时带 `enabled` 与可空 `onTap`，前进/后退两处已经各说一套（那是 ADR-0014"两个必须相等的字段就是一种新的错法"在按钮上的形态）。调用点只许给几何（`size`/`iconSize`，因为"同一行的控件等高"是按表面成立的：树行 20、地址栏 24、git 头 28）。形状统一为圆角方形——参考实现 `ZCode-main/packages/ui/src/components/ui/button.tsx:10,33-37` 是一个 Button 带 `icon-xs/sm/28/32` 尺寸变体、base `rounded-md`、静止比悬停暗一档、禁用 `pointer-events-none opacity-50`，**那个家族里没有圆形**，而原先 `browser_tab`/`git_tab` 两处注释都自称"the source's `.iconButton`"却一个方圆一个圆。**`sidebar.dart` 的 rail `_IconButton` 是登记在守卫里的例外**（rail 上没有文字，图标静止就是 `labelPrimary`；折叠开关在 rail 上同时换字形和字号 24→18，为一枚控件加 `hoverIcon` + 两档字号是 ponytail 反对的那种抽象）。工具的 tooltip 是用户可见文案，必须走 `context.tr`（文件树那枚曾写死 `'Refresh'`，已进字典）。改这块的回归面：`test/icon_button_test.dart`。

**菜单与浮层只有一层皮（ADR-0028 立律，ADR-0036 B6 换了缝）。** 那句话没变：**浮着的一列动作在本应用里只有一层皮，谁画它都一样**；变的是皮住在哪儿。B6 把 `lib/ui` 最后 13 个 Material 菜单入口（`PopupMenuButton` 7 + `showMenu` 6，实测现在都是 **0**）收进 `lib/ui/primitives/menu.dart` 的四枚封装——`DswMenu`（带触发器的下拉）、`DswContextMenu`（右键）、`DswSelect`、`DswSheetPopover`，条目共用 `DswMenuEntry`/`DswMenuRow`/`DswMenuDivider`——于是主题层那枚 `popupMenuTheme` **随 B6 退场**，皮改在 `dsw_shad_bridge.dart` 的 `popoverTheme.decoration` 里说一次（`ShadPopover` 把它并进 select 的 dropdown 与右键菜单，所以一处答完三种形状）。改动前的实测证据仍然成立：Material 的 `colorScheme.surfaceContainer` 在**两个主题里都逐通道等于 `bgLayer1`**（菜单与它浮着的那层同色，只有投影在区分），圆角 4px 而 `DswShape.shell` 的注释自己写着"dropdown menu"，标签走 `labelLarge`（本主题 w500）而真正的动作行都是常规字重。四条实操后果：① **新菜单只认 `primitives/menu.dart`**，别在调用点传 `color:`/`shape:` 重新分叉；守卫是 `test/shad_menu_adoption_test.dart` 的 `no Material menu is left in lib/ui`（扫源码），外加同文件那条 `the scan is looking at a tree that has menus in it`——**扫描对象为空也会绿，所以要反向证一次它看得见菜单**；`test/menu_chrome_test.dart` 仍验皮本身（亮/暗各验填充·圆角+发丝·常规与禁用字样式·悬停 wash，并真开一遍菜单读出浮起那层的皮——**主题项写了不等于挂上了**）。② ADR-0028 那三条 Material 专属机关（`PopupMenuThemeData` 没有 `borderSide` 却靠 `_ShapeBorderPainter` 仍画出发丝、`labelTextStyle` 接管禁用态、悬停 wash 只能走 `ThemeData.hoverColor`）**随换件一起作废**；禁用与悬停现在在封装里说一次（`DswMenuRow` 注的是主题的 `disabledOpacity`，`ink_well.dart:1040` 那条 `hoverColor` 回落仍在，因为 Material 自己的件还吃它）。③ 当年那条"收不动的 `PopupMenuItem` 48.0 行高"也不再是缺口——`DswMenuRow` 给的是内边距而不是钉死高度，行天然跟着字号走（放大文本下的菜单仍归 `amplified_text_probe` 那两档量）。④ 投影故意留在 3.0；**新增主题项之前先问有没有读者**这条不变（`dialogTheme`/`menuBarTheme` 本仓库就没有表面，别补）。改这块的回归面：`test/menu_chrome_test.dart`、`test/shad_menu_adoption_test.dart`，以及"overlay 里的皮与文案都要挂在 `MaterialApp.builder` 那道缝"（ADR-0032）。

**半径阶梯对 shad 的表面也成立（ADR-0029，部分取代 ADR-0002 桥内那条 "No radius/geometry" 省略）。** shad 只有**一枚**半径旋钮（`ShadThemeData.radius`，包默认 6：`shadcn_ui-0.56.3/lib/src/theme/data.dart:113-114`），而 `DswShape` 有阶梯且**头部写着谁该是哪档**（`dsw_shape.dart:17-27`：`float 16` = "a surface that sits above the page … a dialog"，`control 8` = "anything you click: button, field"）。桥以前故意不给这一枚，理由是"别让新组件拿到一个猜来的数"——那条理由没错，错的是留着 6：6 在本系统里的职责是**控件内部的装饰**（row highlight、小徽标），不是任何表面。现在的形状：**旋钮答多数档 `control`**（字段／吐司／对话框里那张卡），**不属于这一档的表面自己在调用点说**——两枚 `ShadDialog` 各传 `radius: BorderRadius.circular(DswShape.float)`。不对称是被迫的，不是设计偏好：一枚旋钮只能答一个数。三条边界：① **不加第七档**（`dsw_shape.dart` 头部写着"加一档要改 ADR-0017"）；② `ShadButton` 的角**不在这条律内**——`button.dart` 根本不读 `theme.radius`（几何来自 `button.dart:970` 的 `ShadDecoration`），要管就得逐点传 decoration；③ 也别给 `ShadInput` 写调用点半径，它读的就是那枚旋钮，桥改完已上阶，再写一份就是第二处真值。改这块的回归面：`test/shad_radius_test.dart`（旋钮等于 `control`／`lib/` 里每一处 `ShadDialog` 构造都必须自报 `radius:`／真开一次确认框读出它渲染的档位）。

**工具卡给人读内容，不读信封（ADR-0031）。** 工具结果是这个产品的主要输出，而显示侧曾经直接套 `JsonEncoder.withIndent`：JSON 编码会把字符串值里的换行转义成字面 `\n`，所以 bash 的 `output`／read 的 `content`／grep 的 `matches` 全塌成一段墙（真窗截图第一次抓到）。现在的律：**线格式给人读的形状 = `formatToolOutput` 一处**（`lib/ui/tool/tool_card.dart`，库级函数）——Map 逐键一行、含换行的值缩进成块、嵌套递归、看着不像 JSON 的散文原样显示；`IN`/`OUT`/摘要三处共用同一个函数，别再让一张卡用两种嗓音。**三条边界**（①② 随 ADR-0031，③ 随 ADR-0035）：① **不要为了 UI 改工具返回形状**（模型要结构，ADR-0012 的契约优先）；② 段落封顶 `maxHeight: 150` 与各自滚动是刻意的（长输入不许埋掉短输出），要加展开 affordance 先说清为什么封顶不够；③ **同一个节点还有别的读者**——详情栏 `details_panel.dart` 曾自带 `_format`（对 String 结果原样返回），所以 ADR-0031 修掉的转义文字墙在右栏一直活着，而两张面在真机上同时可见。律是**改一个共享的东西要问它所有的读者**；判据不是"两处必须一模一样"，而是**被读的地方一份答案，被抄的地方留原文**（详情栏 Input 仍是 `CodeBlock(_pretty(arguments))`，因为用户从那里 Copy 出去的必须是模型形状的 JSON）。改这块的回归面：`test/tool_card_readability_test.dart`（一张卡内部）+ `test/tool_payload_one_voice_test.dart`（两张面之间）。

**语言挂在覆盖层够得着的缝上（ADR-0032）。** `context.tr` 读不到 `AppLocaleScope` 就**逐键回退英文**（`lib/l10n/locales.dart:928-939`，这条兜底是 ADR-0008 给 widget 测试定的，别改）。所以 scope 必须挂在 `MaterialApp.builder` 那道缝上——顺序是 `MediaQuery(字号) → ShadTheme → AppLocaleScope → ShadSonner → child`；**挂在 `home:` 里等于没挂**，因为 `PopupMenuButton`/`showMenu`/对话框的条目活在 overlay 路由里、不是 `home:` 的子树。这条律是 ADR-0017 那次"`MediaQuery` 在 `home:` 进不了 overlay，此前所有点开再量的菜单量的都是没放大的菜单"的**第二次发作**（上次漏字号、这次漏文案），同一个错误在两个通道上说明要的是守卫不是修补。三条实操：① 新增任何**需要进 overlay 的 InheritedWidget**（语言、主题、偏好一类），一律挂这道缝，不要挂 `home:`；② 全应用只留**一枚** locale 座位（守卫按出现次数拦）；③ 菜单/对话框里发现英文残留，先查缝再查字典（`l10n_parity_test` 只拦键，不拦"根本没读 locale"）。改这块的回归面：`test/i18n_overlay_test.dart`（结构那条读 `lib/main.dart` 的缝位置；机制那条真开一次菜单——两条守的不是一件事，缺一条就是瞎的）。

**字段提示是事实声明，不是装饰（ADR-0033）。** 用户会把 hint 里的路径**照敲进 folder picker**，所以一枚假路径就是一个缺陷：设置页 · 扩展 的技能字段曾写 `/Users/you/.dsh/skills`（`.dsh` 是被参考的另一个产品的目录名），而同屏上方两句描述刚说完"为空表示 <应用程序支持目录>/skills"——一处屏上两个真值。律：**提示要么来自运行时真值，要么就不写成绝对路径**。三条实操：① 需要真路径的表面由**装配根**递进来（`SettingsPanel.supportPath` 是必填参数，main 从 `supportDirectoryProvider` 读——widget 不碰 riverpod，规则 5 仍成立），"没有真值可显示"就编译不过；② 举例用 `~/projects/my-app` 这种**不可解析的中性形状**，别编一个 `/Users/you/…`；③ 注释里出现 `.dsh` 是设计来源说明，允许；用户可见字符串里出现就是缺陷（守卫只拦非注释行）。改这块的回归面：`test/settings_reach_test.dart` 的 `a hint is a fact the user can act on` 两条扫描 + `test/settings_test.dart` 那条真开一节读渲染值的断言。

**riverpod 读缝（bridge）。** 把 `ChangeNotifier`/store 桥成**函数式** provider 时，值变更用 `ref.invalidateSelf()`（重跑 body 取新值），**绝不用** `ref.notifyListeners()`——后者对函数式 provider 只重通知旧缓存、不重跑 body，会静默不刷新（且运行日志无异常，只有真机能发现；见 `state/app_providers.dart` 的 `settingsDocument`/`workbenchPrefs`）。该文件现有 19 个 `@Riverpod` 声明；`planObjectStore` 之类默认体直接 `throw UnimplementedError`，是**逼调用方在 `main`/测试里 override**，别把兜底塞回 provider。

**一枚 `pill` 不许长在会缩水的盒子上（ADR-0034）。** Flutter 把圆角半径夹到盒子的一半，所以"完全圆"这枚令牌只对**接近正方**的盒子安全（点、头像）。宽度由内容决定的表面取 `pill` 就会随内容变短而变圆：`_UserBubble` 三字符的 `h'i` 在真窗里渲染成一枚淡蓝圆盘，读作头像而不是"人刚说的话"。律：**半径由"这块表面浮在哪一层"回答，不由"我想让它圆"回答**——气泡与列内卡片同档（`shell 12`），方向性的一角取 `inset 4`（参考实现的 `rounded-tr-xs`），发丝取 `borderL2`（与 popover／菜单同一档，"每一层表面都自己声明边界"）。两条实操：① 边框画在 `DecoratedBox` 的盒子**内部**，加发丝不会把盒子撑大（探针量到改形前后是同一只 83.7 × 44.0 的盒子），"形状变了、座位没变"可以同时成立；② **别拿半径当认 widget 的钥匙**——`chat_view_test` 那条轴守卫曾用 `pill` 认气泡，形状一改它就为错误的理由失败，认法改成按**底色**认（它断言的轴关系一字未改；"改测试"要说清改的是认法还是断言）。改这块的回归面：`test/user_bubble_test.dart`（三条，先红 `+1 -2`）+ `test/chat_view_test.dart`。

**持久化。** 手写 `toJson`/`fromJson` + `dart:convert`（`lib/model/` 里那批 settings/state 模型即范例）。写盘沿用 `lib/state/settings_store.dart`、`prefs_store.dart` 的 tmp + rename 原子写；工作台布局是**每会话一个文件** + 200ms 防抖（`workbench_store.dart` 头部说明了为什么不合并成一份文档）。设置类偏好的真值入口是 `AppSettings` / model 里的 settings 类，新增字段要同时接住全屏设置页与底部快捷菜单（ADR-0006），只接一处就是分叉；**两处接完还得有第三处**——运行时读取点，否则就是 ADR-0022 那四条假开关的第五枚；**字段 hint 不许编绝对路径**（ADR-0033：取运行时真值，或写成 `~/projects/my-app` 这种中性例子）。工作区访问靠 security-scoped bookmark，恢复必须发生在任何读文件之前（`main()` 里的 `restoreWorkspaceAccess`）。跨机搬迁走 `state/backup_service.dart`（zip 打包 settings/prefs/tasks/layouts/sessions/skills/checkpoints）。

## 5. Git 提交（强制）

- 新建 commit 一律用 `git-commit` skill 生成 Conventional Commits 消息：`<type>[scope]: <description>`。
- type 取：feat / fix / refactor / perf / test / docs / build / chore / revert。
- scope 用本仓库的顶层归属名：`genkit`、`model`、`state`、`ui`、`theme`、`l10n`、`host`、`workbench`、`plan`、`macos`、`deps`；`packages/board_panel` 内的改动用 `board_panel`；仓库级配置（`.qoder/`、`.trae/`、`AGENTS.md`、`.gitignore`、`repomix.config.json`、`tool/`）用 `config`；CI 工作流用 `ci`；ADR 与登记表用 `adr` 或 `docs`。
- description 用**英文**现在时祈使句，≤72 字符（与既有历史一致：`C4: the tab strip's right-click menu`）。里程碑式改动可保留早期那种阶段编号前缀，但仍要带 type。
- 破坏性变更用 `feat!:` 或 `BREAKING CHANGE:` footer。
- **主干工作分支是 `develop`**（ADR-0002 的改造面），`main` 可能落后于它；动手前 `git rev-parse --abbrev-ref HEAD` 现场确认，别信任何文档里写死的分支。
- 安全红线（skill 内已申明，此处重申）：永不改 git config、永不 force push / hard reset、永不用 `--no-verify`；钩子失败后修复并**新建** commit，绝不 amend 已存在的提交；一次提交只含一个逻辑变更，按文件/模式分组 add。
- 不提交：`repomix-output.*`、`dart_sources.md`、`.workbuddy/`、`pubspec.lock`（库型包约定，已在 `.gitignore`）、`_archive_project/`（本地归档的第三方参考源码，约 88 MB，2026-09-29 起进 `.gitignore`）、以及任何 API key。`.gitignore` 仍**没有** `*.p12`/`*.cer`/`*.mobileprovision`——引入证书之前先补这几条（`build.md` §4）。
