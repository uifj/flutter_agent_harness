# `docs/user-research/` — 用户证据目录（章程）

## 这个目录为什么存在

截至 2026-10-02，本仓库有 **45 篇 ADR / 一篇生产化差距盘点 / 一篇设计层走查**，全部判据来自代码与竞品源码，**一手用户证据为 0**。这不是努力方向错了，而是它已经跑到了自己的证据天花板：

- `docs/` 里"走查"出现 **151** 次、"真机" **142** 次、"观感" **57** 次、"签收" **35** 次 —— 需要人判断的格子在系统性地堆积，而判断者只有作者一个人。
- 44 篇 ADR 里约 **19 停在 ACCEPTED、7 在 IN-PROGRESS**，能自动化的判据（104 个测试文件 + 七条架构规则 + 两档放大文本尺子挂在 21 个宿主上）已经跑到极限。
- 姊妹项目 `plan-stars`（企划星）**同样没有真实用户**：软件著作权申请表写着"首次发表日期：**未发表**"、`.env` 全指 `localhost:5173`、企划广场的展示数据是硬编码 mock（`apps/web/src/presentation/constants/discover-projects.ts:17` 的 6 条假项目与 `likes: 234 / views: 1892`）。所以它既不是现成的分发渠道，也不是招募池。

于是"这个产品到底有没有人要"目前是一个**没有证据的开放问题**，而形态②（账号 + 消费订阅）已经把最大的成本项（服务端）押在这个问题上了。本目录的作用就是把这件事变成有证据、可证伪、带截止日的东西。

## "出实效"的定义（每篇都必须满足，否则别写进来）

一份研究产出只有满足下面三条才算完成：

1. **绑定一个会改变行动的决策问题**（DQ-n）。写不出"哪个答案会让我不做某件事"的问题，就不值得研究。
2. **带证伪判据**：一个数字或一个可观察行为（例如"10 人里至少 3 人在没被提示的情况下自己点发布"），并写明**达不到就停止什么**。
3. **带截止日期与样本来源**：谁、从哪来、几个人、什么时候聊完。没有招募路径的研究是自我对话。

允许"没有结论"，不允许"没有判据"。

## 文件约定

| 类型 | 命名 | 内容 |
| --- | --- | --- |
| 大纲 | `outline-YYYY-MM-DD.md` | 决策问题、假设矩阵、招募、方法、度量、排期、kill criteria |
| 单次记录 | `note-<代号>-YYYY-MM-DD.md` | 一人一篇：**原话编号（Q-01…）与我的观察分栏**，不写解释 |
| 归纳 | `synthesis-YYYY-MM-DD.md` | 主题 → JTBD → 机会点，每条必须挂回 ≥2 个原话编号 |
| 度量 | `metrics-YYYY-MM-DD.md` | NSM / driver / counter / health + 埋点缺口清单 |

## 证据标准（写进来之前先自检）

- **区分三种东西**：一手观察（我亲眼看见他做了什么）、用户自陈（他说的）、我的推断（我猜的）。三者必须分栏，混写即作废。
- **作者在场要标注**。作者是开发者本人坐在旁边看的会话，天然会软化评价；这类记录顶部必须写"观察者效应未消除"，并且在归纳时**降权**，不与远程独立测试同权。
- **不拿 A 池的答案回答 B 池的问题**（工程师 vs 大学生创作者是两种 job，见大纲 §3）。
- **负结果照记**。"查了，不是缺陷"也要写一条——本目录第一条这样的记录在 `deep-dive` §4 末尾（关于设置写盘是否回表明文密钥）。

## 与 ADR 的强制关系（**这条规则本身待用户批准**）

建议加进 `docs/README.md` 的"新增 ADR 流程"第 2 步：

> 凡涉及**人群 / 收费 / 商用形态 / 发布边界**的 ADR，"背景"段必须引用 `docs/user-research/` 里的一个编号（原话或归纳条目），**或者显式写"无一手证据，作者推断"**。

理由：今天的现实是 `docs/production-readiness-gap-2026-10-02.md` 里"国内商用刚需""获客利器""商用 BYOK 的基本盘"这类判断，全部是从**竞品代码里存在某个功能**反推出来的，零一手证据。这条规则不阻止你下判断，它要求你把判断的性质签清楚。我**没有**擅自改 `docs/README.md`、`AGENTS.md` 或 `.qoder/`/`.trae/` 规则文档——那需要你先拍板。
