# 用户研究大纲 · 出实效版（2026-10-02）

> **一句话目的**：在往形态②（账号 + 消费订阅）的服务端里再写一行代码之前，用两周时间拿到一个信号——**有没有陌生人愿意让一个 agent 进自己的文件夹，并且把自己写的 `.md` 发布出去**。

## 1. 决策问题（DQ）——只问会改变行动的问题

| # | 问题 | 哪个答案会让我**不做**某件事 | 最便宜的测法 | 判据 |
| --- | --- | --- | --- | --- |
| DQ1 | 目标人群是"写代码的人"还是"做企划的人"？（两个产品的答案不一样） | 若是后者：停掉代理面的复杂度（工具环、审批、终端），并停掉对工程师的叙事 | 两池各 5 人，同一套任务，比谁在 10 分钟内**要求更多**而不是抱怨更少 | ≥3/5 的人主动问"能接我现有仓库吗"（A 池信号）或"能给我同学看吗"（B 池信号） |
| DQ2 | "agent 和企划在**同一个文件夹**"是不是陌生人 30 秒内能理解并想要的卖点？ | 若不能：把它降级为实现细节，不当主叙事，也就不必为"两面并存"付产品复杂度 | 冷启动一句话介绍（不演示），复述测试：他说出的是什么 | ≥4/8 的人复述出"改我本地文件 + 我能发出去"两个要素 |
| DQ3 | 有没有人真的会发布自己的 `.md`？为了什么观众？ | 若没人要：形态②的外循环（发布→分享→拉新）整体作废，服务端只留账号与额度 | 让他在 10 分钟任务里**真的发一条**，然后问"你会把它发给谁" | 发出去且**主动说出一个具体接收对象**（老师/同学/同事/社群）≥3/8 |
| DQ4 | 付费单位是"模型额度"还是"发布位/协作位"？（企划星的 3 元/7 元是断言，无验证） | 若是后者：额度页不是 MVP 核心；若是前者：企划星的 VIP 结构不能照搬 | 直接问价，用 Van Westendorp 四问简化版（太贵/贵但可接受/便宜/太便宜不敢信） | 拿到一条**价格带**，而不是"看情况"；≥2 人主动问"多少钱/怎么付" |
| DQ5 | 审批 + 可回退（本仓库唯一的差异化资产）在陌生人眼里是安心还是麻烦？ | 若是麻烦：ADR-0012/0014 那套门禁要在 MVP 里默认关闭，差异化重估 | 让他第一次遇到中断，记录他是**读**弹窗还是**连点通过**；事后问刚才那一条批准了什么 | 读弹窗 ≥4/8 且答对内容 ≥3/4 人；否则"审批=噪音" |
| DQ6 | 已经习惯 BYOK 的人，会不会接受必须登录账号？ | 若强烈反弹：形态②要保留 BYOK 双轨（成本大），或先做① | A 池里找 3 个现在用 CLI agent 的人，问"如果必须登录才能用，你会怎样" | ≥2 人说会走别的工具 = 双轨必要 |

**注意 DQ1 与 DQ2 是地基**：现在的代码把两面并存当作既定事实（ADR-0007/0037/0044 + 32,074 行企划面），而它成立的技术前提（同一工作区）有一半是假的（§0 第三行）。技术上不成立的产品叙事，不会因为没有 ADR 就自动成立。

## 3. 样本与招募（不许串池）

| 池 | 是谁 | 从哪来 | 目标 n | 回答哪些 DQ |
| --- | --- | --- | --- | --- |
| **A · 写代码的人** | 现在在用 CLI/IDE agent 的工程师（含独立开发者） | 即刻/V2EX/GitHub 上的 agent 话题、身边同事；**禁止用企划星用户充数** | 8–10 | DQ1、DQ5、DQ6、DQ2 |
| **B · 做企划的人** | 大学生/社团/个人创作者（企划星 §一定位的人群） | 课程群、社团负责人、小红书/即刻的创作话题 | 8–10 | DQ1、DQ3、DQ4、DQ2 |

招募硬规则：**A 池的答案不能回答 B 池的问题**，反向也一样（章程 §证据标准）。每条记录一人一篇 `note-<代号>-*.md`，顶部写来源渠道与是否作者在场。

## 4. 方法

**4.1 十个分钟远程任务（两池同一套）**
1. 选一个**你自己真实在用的文件夹**（不许用演示目录）。记录他实际选了哪个——这一步就是 DQ1 的答案。
2. 让 agent 做一次小改动（例如"给这个笔记加一个待办清单"）。记录他**是否读审批**（DQ5）、是否用了 rewind、还是先问"这会不会毁了我的文件"。
3. 把一篇 `.md` 发布成链接。记录他发给谁（DQ3）、以及他是否期望链接能被搜索到/被同事看到。

**4.2 五段访谈提纲**（15–20 分钟，一人一次）
① 情境：你现在怎么把想法变成可执行计划？最近一次是什么项目？② workaround：用了什么工具，最烦哪一步；③ 尝试：刚才那三个任务，哪个和你现在的做法不一样；④ 痛点复述：他主动抱怨的（不是我引导的）；⑤ 价值：DQ4 的四问价带 + "如果它明天收费 X，你下个月还会开吗"。

**4.3 反偏见提示（写进每篇记录顶部）**
- 作者在场会软化评价 → 该类记录降权，不与远程独立测试同权。
- "你觉不觉得好用"是废问题；只问**上一次你做这件事是什么时候、怎么做的**。
- 不要卖产品。他一表达热情就转成"那你下周会用它做哪件具体的事"。
- 5 人以上同向才算主题；2 人就写"未成型"。

## 5. 度量（零遥测约束下的可执行版本）

**North Star（候选，需 DQ1 结果来定）**：每周"真实文件夹里完成的 agent 任务数"——不是会话数，不是消息数。

| 层 | 指标 | 现在能不能量 |
| --- | --- | --- |
| Driver | 第一次任务成功率（10 分钟内完成且没求助） | 能量：现场记录 |
| Driver | 发布率（完成任务的人里发出链接的比例） | 能量：现场记录 / 服务端 share 行 |
| Driver | 价格带（Van Westendorp 可接受区间） | 能量：访谈 |
| Counter | 审批连点通过率（读都没读就通过） | 能量：现场观察 |
| Counter | 求助次数（需要主持人提示才能推进） | 能量：现场记录 |
| Health | 每次任务的 token 成本（用 `UsageLedger` 导出的真实条目） | **能量**，且不需要新代码：`lib/state/usage_ledger.dart` 已在记，`main.dart:94-98` 启动就 prune + summarize，保留 30 天 |

**埋点缺口（诚实清单）**：全仓**零遥测**（那 18 处 `analytics` 类命中全是 `GitStatusEntry` 假阳性），崩溃**已经留痕**（`lib/state/crash_archive.dart`），应用内帮助仍为 0。所以 MVP 阶段任何"上线后看数据"的说法都不成立——没有数据管道；能用的只有现场观察、用户自陈，以及本地 `UsageLedger` / 崩溃归档的**导出**。剩那一格要做的事是"一键把诊断递出来"（见 §8 第 6 格与 `deep-dive` §6 第 5 条），这条比新增任何功能都更影响决策速度。

## 6. 两周排期与 kill criteria

- **W1**：DQ1/DQ2/DQ5（远程独立主持，避免作者在场偏见）；A 池 5 人、B 池 5 人。
- **W2**：DQ3/DQ4/DQ6；各池补到 8 人；写 `synthesis-2026-10-16.md`。
- **继续投形态②的条件（三条全中）**：≥4/8 复述出双要素（DQ2）**且** ≥3/8 发出链接并说出接收对象（DQ3）**且** 拿到一条含上限的价格带且 ≥2 人主动问价（DQ4）。
- **Kill / 转向**：
  - DQ3 不达 → 外循环作废，服务端只保留账号 + 额度，**停掉发布相关一切新功能**；
  - DQ1 B 池显著更强 → 主用户是创作者不是工程师，代理面转为次要（此时"两面并存"变成需要重新论证的决策，不是前提）；
  - DQ6 反弹 ≥2/3 → 必须保留 BYOK 双轨，形态②成本重估；
  - 两条以上不达 → 回到形态①或开源路线，把工程精力转向"让人看见"（`README.md` 仍是 pub 模板这件事在此路线下是头号缺口）。

## 7. 明确不做（本轮范围内）

协同编辑 / 在线光标 / CRDT 合并 / 块级评论 / 团队座位与权限矩阵 / 企划广场的内容审核与推荐 / 举报与敏感词运营 / 移动端。**"不做协同编辑"是有结构理由的**：企划星的分享本来就是**冻结快照**（`workspace-shares.route.ts:50-130`），不需要实时合并就能成立——这条决策让发布路径成为最短的一条（详见 `deep-dive` §4）。

## 8. 最小 MVP（形态②成立后，两面并存的前提之下）

判据仍然是一句话：**陌生人 10 分钟内拿到第一次价值，而你能记账**。但内容按"两面并存"重排过，与我上一轮的版本不同（见 §9 撤回记录）。

**进 MVP 的六格**：

1. **登录取代设置首屏**：`lib/main.dart:124`/`:269` 那道"没配 key 就把整个界面换成设置页"的门要反过来——没登录是登录页，登录了直接进工作区，模型由服务端代理（ADR-0045 的自建后端）。这一格同时解掉 `deep-dive` §7 的机会 #4，是**第一号的可用性债**：现在的冷启动要求陌生人先读懂 `endpoint / Base URL / provider` 才看得到产品。
2. **一条完整代理闭环**：审批 → 工具环 → 写文件 → **rewind**（ADR-0012/0014/0016 欠的那笔正好在这里）。这是差异化本体，不是收尾项。
3. **企划面在同一批 `.md` 上组织**：集合/视图/块编辑器都保留，但 MVP 里它的作用被重新定义为**"把 agent 写下的东西读成结构"**（大纲 §7 机会 #2），不是复刻 Anytype 的全部功能面。因此面内可以砍：GRAPH/embed 占位照旧不支持（按上游答案）、`@提及面板` 与封面/对象图标选择器（对照表里 🔨 的 UX 可见项）不进 MVP。
4. **发布出口**：一篇 `.md` → 冻结快照 → 公开链接（owner 关闭 / 到期失效，对面已实现）。**前置三件事**（都还没定，见 §10）：发布单位、对象库归属、`Workspace` 改名。
5. **额度改成账单语义**：设置里的 usage 一节**已经存在**（`lib/ui/settings/model_settings.dart:574`、`:1374`，读 `usageSummaryProvider`），本机用量也已落账（`lib/state/usage_ledger.dart:69-77`，保留 30 天）。MVP 缺的不是面板，是**服务端侧的配额语义**：这个月还能用多少、超了怎么说、模型侧失败或离线算不算用户的额度——这三格在两份文档里都还没有归属。
6. **把诊断递到用户手里**：崩溃**已经在归档**（`crash_archive.dart` + `main.dart:74`），`crashArchiveNonEmptyProvider` 说明界面会读它。MVP 要确认的是那一格能不能**一键带走**（reveal / 打包成一份附件），否则用户只能描述"它闪退了"。这是 §6 待验清单里的一条，我没能当场证实。

**不进 MVP**：MCP、子 agent、备份/恢复、tray 与全局热键、图片/PDF 附件、browser tab、终端与 diff 的写操作、协同编辑。依据沿用 `docs/production-readiness-gap-2026-10-02.md` §5 那句"功能越多暴露面越大"。

**已闭、不必再排进来的**：上一轮我列的「地基四件」——明文密钥、设置损坏隔离、崩溃留痕、重置入口——**四件全部已落**（证据见 §0 最后一行）。`P0-2 版本事实`也随 `751f779` 闭（`pubspec.yaml:3` 已是 `0.1.0`，README/CHANGELOG 已是真文档）。**只剩 P0-1 签名/公证 与 P0-6 许可声明（LICENSE + 第三方声明）**，两条都是发出去前一周的活。

## 10. 锚点定案（2026-10-02，竞品实扫后）

| 锚点 | 状态 | 内容与依据 |
| --- | --- | --- |
| **① 发布的最小单位** | ✅ **用户已定** | **一个企划 = 一个工作区 = 一个可阅读站点**（参照 [krahets/hello-algo](https://github.com/krahets/hello-algo)：MkDocs + `docs/` + 5 语言 + 130.6k stars）。**不是**发布单篇 `.md` |
| **② `plan_space.json` 的归属** | ✅ **被①逼出，非偏好** | 必须 **per-workspace**。现状是 Application Support 下唯一一份全局文件（`lib/main.dart:106`，切工作区不动）——发布时会把 A 项目的集合与 B 项目的记录混进同一个站点，「这个企划的边界」根本无法确定。**这是发布功能的第一前置** |
| **③ 第一批人群** | ✅ **押 A 池，且 A 池重定义** | 举 hello-algo 当参照，动机就是「把本地文件夹里的知识组织成给别人读的东西」。画像=**写代码也写东西的人**（开源维护者 / 技术作者 / 讲师 / 写方案的工程师）——与 Obsidian Publish、Mintlify、GitBook 的买家画像同向。**不是**企划星 §1 的「大学生社团协作」（那是要协同编辑的人群，而我们明确不做协同编辑）。B 池降为次要，仍不许串池 |
| **④ 定价与计费单位** | ⬜ **新留的锚点，待一手验证** | 企划星的 3 元/7 元与外部市场差一个数量级（Obsidian Publish **$8–10/站/月**、Copilot Pro **$10/月**、Mintlify Pro **$450/月**），且它的阶梯按**容量**计，回答不了「我发 3 个企划站点要付多少」。按①的新单位，「每站点/月」与「模型额度池」是两条候选轴——用 DQ4 的价带问法验，别照抄竞品 |

**由①直接改写的两格**：MVP 第 4 格从「发一篇」变成「**发一个企划成站点**」（阅读件缺口清单见 [`bench-2026-10-02.md`](bench-2026-10-02.md) §8）；DQ3 的判据也跟着改——不再问「会不会发一篇」，而问「**会不会把整个企划发出去，并且说出给谁看**」。
