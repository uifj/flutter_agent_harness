# 竞品实扫 · "把本地 .md 发成可阅读站点"这一族（2026-10-02）

> **方法**：WebSearch + WebFetch 现场实扫（2026-10-02），每个数字带来源；与 [`docs/zcode-vs-agent-harness-2026-09.md`](../zcode-vs-agent-harness-2026-09.md) 的边界是：那篇比的是**内部代码**（ZCode 86.1 万行），本篇比的是**外部市场与定价**。
> **触发**：用户定了锚点①——发布的最小单位是**一个企划（= 一个工作区）= 一个可阅读站点**，参照物是 [krahets/hello-algo](https://github.com/krahets/hello-algo)（截图给的就是它的阅读界面），**不是发布单个 md 页面**。
> **本篇要回答的问题**：这个形态有没有人做过、卖多少钱、留下什么空白、以及它把哪两个锚点逼出来了。

## 1. 参照物解剖：hello-algo 的阅读件清单

| 维度 | 实测 |
| --- | --- |
| 生成器与配置 | MkDocs，配置在仓库根 `mkdocs.yml` |
| 内容组织 | `docs/` 为正文，翻译各占目录：`en/`、`ja/`、`ru/`、`zh-hant/`（共 **5 种语言**） |
| 代码 | `codes/` 目录集中放**多语言实现**，卖点是"动画图解、**一键运行**" |
| 采用度 | **130.6k stars / 15.5k forks** |
| 部署 | GitHub Actions（`.github/` 下的 workflow） |

从截图（阅读态）反推，一个"可阅读站点"的**必备件**是：左侧**章节树**（可折叠、当前项高亮）、右侧**页内目录 TOC**、正文**最大宽度居中**、明暗切换、**全文搜索（⌘K）**、语言切换、上下章导航、代码块带语言标签。

**这条判断很关键**：这套东西**免费工具一条命令就能拿到**（MkDocs Material / VitePress / Docusaurus 全都给）。所以——**发布不能是我们的收费支点**（见 §6）。

## 2. 直接对手：同一个 job（本地 .md → 站点）

| 产品 | 定价（实扫原文） | 发布形态 | 留下什么空白 |
| --- | --- | --- | --- |
| **Obsidian Publish** | **$8/月（年付）或 $10/月，"Per site, per month"**；Sync $4–5/用户/月；Catalyst $25 一次性；**无免费试用**（仅 7 天退款） | 本地 vault 直接发布；自带**图谱**与**全文搜索**、主题可定制；官方页未列自定义域名与细粒度访问控制 | **按"站点"计费**——与"一个企划=一个站点"完全同构，是最该研究的一例。但它**没有 agent、没有数据视图、代码不能运行**，且发布的是本地文件的镜像而非可组织结构 |
| **Notion Sites** | 免费可发**无限页面**；自定义域名是付费档之上的 add-on，**$10/月（年付 $8/月）**，一个 add-on 一个地址，一个工作区最多 25 个 | **页面级发布，自动带子页**；官方明说**不会把整个数据库/工作区批量导出成统一多页站点** | 数据库→站点的整站发布是它的缺口（正是我们锚点①要做的事）；但它的免费额度极宽，**"能发布"本身不构成付费理由** |

## 3. 相邻族：文档平台（不是同一 job，但同一批买家）

- **Mintlify**：**Pro $450/月（年付）**，AI 能力按 credit 计量、用完另计费；买家画像=**要像素级样式自主权的工程团队**。
- **GitBook**：**每站固定费 + 每用户**，卖点是拖拽结构管理与可预测账单，AI agent / MCP 要付费档；买家=跨职能团队（非工程主导）。
- 两者都是 **git-based sync 公开可用**（不锁在付费档）。

**读法**：$8–10（个人，Obsidian Publish）与 $450（团队，Mintlify）之间是空的——但那块空**已经被免费静态生成器占着**。所以这不是"我们去做那个空档"，而是**警示：把发布当商品会直接对上免费工具**。

## 4. agent 工作台族：订阅锚与额度语义

GitHub Copilot 官方档位（实扫）：

| 档 | 价 | 用量语义 |
| --- | --- | --- |
| Free | $0 | 2,000 completions + 50 chat requests，agent 会话同池 |
| **Pro** | **$10/月** | **1,500 credits/月 + $5 flex**；补全与 inline edit 不限；超额按 **$0.01/credit** 购买 |
| Pro+ | 未列 | credits "比 Pro 多 4.6× 以上"，含 $31 flex |
| Business | $19/用户/月 | 1,900 credits/许可，flex 关闭，管理员设预算上限，超了就停到下个周期 |
| Enterprise | $39/用户/月 | 组织级池化 credits |
| Max | 未列 | **$200/月总 credits + $100 flex**，在 **75% / 90% / 100%** 三档主动提醒 |

另一篇行业分析标题直接是 **"Flat-Rate AI Is Dead"**（Copilot/Cursor 的计费从包月转向按用量）——**按 credit 池 + flex 额度 + 阈值提醒 + 超额可购**正在成为惯例。

**这四件事是我们额度页可直接抄的语义**（本仓库已有 `UsageLedger` 与设置里的 usage 节，缺的正是这套池/阈值/超额表达）。**入门价的心理锚也定了：$10 ≈ ¥72**，开发者工具的主流入门档。

## 5. 企划星现在押的位置（对照，不是照抄）

`plan-stars/doc/01.项目定位与业务设计.md:472-493` 的 VIP 体系是 **免费 / 3 元 / 7 元**，且**计费单位是容量**（企划数、成员数、任务数、事件数、附件开关）。与外部实扫对照有两处硬冲突：

1. **价格带差一个数量级**：$8–10/站/月（Obsidian Publish）≈ ¥58–72；3 元/7 元在这个市场里连成本都盖不住，尤其还要付模型 token。
2. **计费单位与锚点①不匹配**：现在发布的最小单位是**站点**，那"每站每月"就是天然的计费轴（Obsidian 已验证这个单位），而容量阶梯回答不了"我发了 3 个企划站点要付多少"。

→ **锚点④（新）：定价与计费单位要重画**，且这是**产品决策不是功能清单**，需要一手验证（大纲 DQ4 的价带问法）。

## 6. 空白与差异化（判词）

**没有人同时做这三件事**：① agent 在**你自己的文件夹**里改文件且**每步可回退**（before 镜像 + 冲突闸门，`lib/model/checkpoint.dart` / `lib/state/checkpoint_store.dart`）；② 同一批 `.md` 被组织成**集合与视图**（`lib/ui/plan/`）；③ 一键把整个企划**发成可阅读站点**。
Obsidian 有 ② 的雏形和 ③（Publish），没有 ①；Cursor/Copilot 有 ① 的雏形，没有 ② ③；Notion 有 ③ 的壳，明说不做整站；Anytype 有 ② 的强版本，③ 与 ① 都没有。

**但付费理由必须落在生产端（①+②），发布只是出口与传播。** 理由就是 §1：阅读态是免费商品。反过来说，发布仍是**最好的获客面**——每个发出去的站点都是 hello-algo 式的名片，这属于**外循环/增长**，不属于**商品本身**。这条区分决定了付费墙该画在哪：额度与 agent 能力在墙内，阅读与分享在墙外。

## 7. 实扫直接逼出的两个锚点定案

- **锚点②（`plan_space.json` 归属）→ 必须 per-workspace。** 这不是偏好，是被锚点①逼出来的：如果发布单位是"一个企划=一个工作区=一个站点"，而对象库是**跨项目共享的一份全局文件**（现状：`lib/main.dart:106` 开在 Application Support，切工作区不动），那"这个企划的边界"根本无法确定——发布时会把 A 项目的集合与 B 项目的记录混进同一个站点。**这条现在是形态②发布功能的第一前置。**
- **锚点③（第一批人群）→ 押 A 池，且 A 池要重新定义。** 用户举的例子（hello-algo）本身就说明动机是"**把我在本地文件夹里的知识组织成给别人读的东西**"。这个人的画像是：**写代码也写东西的人**——开源维护者、技术作者、讲师、写方案与文档的工程师（Mintlify/GitBook/Obsidian Publish 的买家画像全部指向这里）。**不是**企划星 §1 写的"大学生/社团协作"（那是要协作编辑的人群，而我们已经明确不做协同编辑）。B 池降为次要，且**不许用 B 池的答案回答 A 池的问题**。

## 8. 发布页必须做到的阅读件（对面契约的缺口清单）

| 件 | 对面（企划星）现状 | 缺口 |
| --- | --- | --- |
| 页面树 / 多页 | **已有**：分享就是页面树快照（`workspace-shares.route.ts:50-130` 从快照重建页面树） | 需确认分享页是否渲染**跨页导航**（`WorkspaceSharedPage.tsx` 现在喂的是单页 BlockNote） |
| owner 关闭 / 到期失效 | 已有（`active`/`disabled`/`expired`，`expires_at` + RLS） | — |
| 公开留言 | 已有（需登录，不入协作线程） | — |
| 章节侧栏 + 当前项高亮 | 未见 | **要做** |
| 页内 TOC / 上下章 | 未见 | **要做** |
| 全文搜索 | 未见（分享域） | **要做**，且要预算（对面 view count 是原子自增，搜索是另一回事） |
| 明暗 / 最大宽度居中 | 未见 | **要做**（本仓库设计层已有 `bgLayer*`/`borderL2` 一套皮，可同源） |
| 多语言 | 未见 | hello-algo 有 5 语；我们**先不做**，但目录结构要留位 |
| 代码块运行 | 未见 | "一键运行"是参照物的核心卖点之一，MVP 不做，但**代码块要保住语言标签** |

## 9. 待验（不当结论用）

1. 对面分享页能否承载**多页导航 + TOC + 搜索**（§8 三条"未见"要实跑一次才算）。
2. `.md` → BlockNote 的映射对**多页目录、代码块语言标签、表格与本仓库的 `<!-- plan:{json} -->` 信封块**能保住多少。
3. Obsidian Publish 到底能不能自定义域名/做访问控制——官方 pricing 页未列，但产品其他页与社区说法不一致，**需复核**再引用。
6. **今日抓不到 Publish 的 help 页**（`help.obsidian.md` 与 `obsidian.md/publish` 两次 WebFetch 失败），所以它的**选择模型**（哪些笔记进站点）、**侧栏组织**（手工分组还是目录镜像）、**变更确认**（显式发布还是自动同步）三格**未核**。已核的只有 pricing 页那四句（"Publish notes to the web"、"No technical knowledge required"、"Customizable theme"、"Graph and full text search"）与价格。ADR-0047 的决策 1（内容 = 文件）不依赖这三格；决策 3/4 依赖，已在该 ADR 的验证 5 里挂成复核项。
4. 上面所有价格都是 2026-10-02 抓取的公开页，会漂移；引用前重跑。
