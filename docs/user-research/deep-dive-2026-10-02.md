# 深入研究 · 两面的共享工作区与"发布 .md"这条路（2026-10-02）

> 本篇是 `outline-2026-10-02.md` 的分析底座：把"两面都保留，因为它们共享工作区"这句话**验到代码行**，指出它成立的那一半、不成立的那一半，以及"发布自己工作区的 md"这句话里一个还没被发现的歧义。全程只读代码，不产代码。

## 1. 组合现状：两个零用户产品，一份可复用的契约

| | agent_harness（本仓库） | plan-stars / 企划星 |
| --- | --- | --- |
| 形态 | Flutter 桌面（mac/win/linux），本地文件为真值 | Web（Vite + BlockNote + Supabase + Node 服务端） |
| 定位人群 | 未写（AGENTS.md 只讲技术栈；README 是 pub 模板） | 明确写了：**大学生 / 个人创作者**（`doc/01.项目定位与业务设计.md:9`） |
| 真实用户 | **0**（作者自陈） | **0**：软著表"首次发表日期：**未发表**"、`.env` 全 `localhost:5173`、广场 showcase 是硬编码 mock（`apps/web/src/presentation/constants/discover-projects.ts:17`，`likes: 234 / views: 1892`） |
| 服务端 | 无（形态②要靠对面或新建） | 已有 CRUD + owner-only 分享 + 快照 + 到期 + 登录留言 |

结论很直接：**企划星是"契约与 schema 资产"，不是"分发渠道"，也不是招募池**。任何"我们的用户来自企划星"的假设现在都不成立，所以大纲 §3 要求两池分开招。

## 2. "共享工作区"：成立的那一半，和不成立的那一半

**成立的那一半（而且比想象的更强）**：

- 工作区只有一个真值：`AppSettings.workspaceRoot`（`lib/model/app_settings.dart:162`），切换只有一条路（`lib/state/app_scope.dart:428 withWorkspace`）。
- 代理面把它当作**唯一安全边界**：`lib/model/workspace.dart:1-12` 头部写着"the app's one security boundary"，`resolve()` 先解符号链接再拒绝越界（`:50-59`）。
- 企划面的 vault 树读的就是**同一个 root、同一批 `.md`**：`lib/ui/plan/plan_workspace.dart:11` 的注释原话——"`workspaceRoot` the file tools are confined to) — there is no separate vault"；`_treeFooter` 之外，正文读写是 `File(p.join(root, note.relative))`（读 `:219`，写 `:247`），新建笔记也落在同一 root（`:519/:528`）。
- 所以 **"agent 写的文件"与"企划面编辑的笔记"是同一批字节**。这不是巧合，是 ADR-0037 的设计意图（"盘上格式仍然是工作区里的 `.md`，没有第二份文档库"）。这是本组合里**唯一一个竞品都没有的结构优势**（见 §3）。

**不成立的那一半（这条会咬人）**：

- 企划的**对象库**不在工作区里。`PlanObjectStore.open(support, …)`（`lib/main.dart:106`）把集合/记录/类型/关系/模板/组件写进 **Application Support 下唯一一份 `plan_space.json`**（`lib/state/plan_object_store.dart:95-106`，写盘 `:1211-1213`），启动时 `overrideWithValue` 一次（`main.dart:124`），**切工作区它不跟着走**（`plan_workspace.dart:111` 只重建那棵树）。
- 而笔记在账本里是以 **workspace-relative path** 引用的（`:82` 注释"the selected note's workspace-relative path"，`:140/:165/:185`）。
- 于是三个后果：
  1. **换项目，集合还是那一堆**（还是 mock 种子 `planMockSeed()`）。用户看到的不是"这个项目的企划"，是"我所有项目共用的一个企划库"。
  2. 两个项目里存在同名相对路径（`notes/plan.md` 这种极常见）时，它们在全局账本里指向同一个相对键——**是否会串，我没实测**，列进 §6 待验。
  3. 形态②一旦账号化，`plan_space.json` 必须先回答它是"**个人的全局库**"还是"**每个项目一份**"。这个答案直接决定发布/同步的对象归属，且它现在**没有任何 ADR 写过**。

判词：**两面共享的是文件，不是对象库。**"同一工作区所以两面并存"这句在正文层为真、在数据层为半真——写 ADR 时如果按"全真"来定产品叙事，服务端会替你把这半条裂缝放大成归属 bug。

## 3. 唯一值得讲的差异化故事（发布功能的出发点）

把 §2 成立的那一半摊开，这个产品的独特叙述只有一句：

> **agent 在你真实的文件夹里干活（改动可回退），你把同一批文件组织成集合与视图，然后把其中一篇发出去给人看。**

对照竞品：**Anytype** 有数据视图没有 agent；**ZCode / Claude Code** 有 agent 没有数据视图也没有发布；**企划星**有发布与协作但没有本地 agent，也不碰你磁盘上的 `.md`。三面同时具备的目前是空白——而这一空白正好落在本仓库已经付过成本的两面上（`lib/ui/plan` 10,579 行 + `plan_*` 6,289 行 + `packages/board_panel` 15,206 行 = 32,074 行，约占全仓产品代码 72,254 行的 **44%**）。

**这条也是"两面都保留"最强的论据**——比"共享工作区"更强，因为它讲的是**用户拿到什么**，而不是**代码怎么搭的**。

## 4. "发布自己工作区的 md"的歧义 → **已定案：企划级站点**（原分析保留）

企划星的分享契约是 **workspace（=企划）级 + 页面树快照**（`apps/server/src/application/use-cases/manage-workspace-share.use-case.ts:62` owner-only、`:39` 状态机 `active|not_found|disabled|expired`、快照替代实时树 `workspace-shares.route.ts:50-130`）。而你想发的东西是"工作区里的 `.md`"。这两个"工作区"不是一个东西：

| | harness 的 Workspace | 企划星的 Workspace |
| --- | --- | --- |
| 是什么 | 本地目录 + 安全边界（`workspace.dart:37-59`） | 远程多租户企划/账户单元（`packages/shared/src/domain/entities/workspace/workspace.ts:8-11`，注释直接写"企划生命周期状态"） |
| 后果 | **撞名，不是同义**。共享 DTO/API 时必有一侧改名 | 同左 |

于是"发布"有两个候选宾语，成本差一层转换：

- **单位 = 一篇 `.md`（文件语义）**
  - 路径 1「blob 直发」：harness 上传原文，分享页自己 md→HTML。**改动最小**，但发布物不在企划星的对象模型里 → 广场/搜索/评论/RLS 要不要覆盖它得重新定义。
  - 路径 2「转成块模型」：md → BlockNote blocks → Y.Doc。服务端已有 `@blocknote/server-util`（`apps/server/src/interface/http/setMark.ts:17` 已 import）。发布物天然进入 page tree / snapshot / comment 全套，**但**要新建一条 md↔block 语义映射，并且它**必须永远一致**——本仓库的 `.md` 里还有一行 `<!-- plan:{json} -->` 信封承载 md 装不下的块（`lib/model/plan_markdown_codec.dart`），那套语义映射测试不是小活。
- **单位 = 一个企划（对象语义）**：必须先解决 §2 的对象库归属（全局 vs per-project），而它现在是 mock 种子。走这条路，发布的前提是"对象库真实且属于这个项目"。

> **定案（2026-10-02）续：站点页面从哪来也已决**——内容 = 工作区里的 `.md` 文件，企划 = 发布清单（记录加一条 `sourcePath`），见 `docs/adr/ADR-0047-arc-site-content-is-the-md-file-plan-is-the-manifest.md`。
> **定案（2026-10-02）**：选这条。**发布单位 = 一个企划 = 一个工作区 = 一个可阅读站点**，参照 hello-algo（MkDocs、`docs/` + `en/`/`ja/`/`ru/`/`zh-hant/`、`codes/`、130.6k stars）。两条直接后果：① §2 的对象库归属**不再是开放问题**，必须 per-workspace；② 对面已有的**页面树快照**契约本来就是多页的（`workspace-shares.route.ts:50-130`），所以「多页」这一项并不比单页贵——真正贵的是**阅读件**（章节树 / 页内 TOC / 跨页导航 / 全文搜索），清单与缺口见 [`bench-2026-10-02.md`](bench-2026-10-02.md) §8。

**"不做协同编辑"让这条路显著变短**——这不是妥协，是选对了机制：企划星的分享本来就是**冻结快照**（`doc/sql/migrations/20260720_workspace_share_snapshot_pages.sql:18` 把内容冻成 `ydoc_content bytea`；`workspace-shares.route.ts:50-130` 有快照就替代实时树；owner 关闭 + `expires_at` 已实现）。快照不需要 CRDT、在线光标、冲突合并。所以本仓库那条"暂不做协同编辑"的决定与对面的分享契约**天然同构**，反而绕开了企划星里最贵的那部分（`collab_states.ydoc` 那套实时协作）。

**另一条要记的边界**：企划星自己的 AI prompt 明写"不要 Markdown"（`packages/shared/src/ai/prompts.ts:24,37`）。也就是对面整个内容世界观是块，不是 md。harness 的世界观正好相反（md 是唯一盘上格式）。**发布是这两个世界观的接缝**，接缝上必须有人做一次转换或一次原样透传——这是"选单位"这个决策的真实内容，不是命名问题。

## 5. 契约层改名（越晚越贵）

建议：**harness 侧对外（任何共享 DTO）称 `Vault` 或 `Folder`**（企划面本来就叫 vault），服务端保留 `Workspace`。理由：harness 内部已经有六个地方按 `workspaceRoot` 这个词长了依赖——会话归属 sidecar（`app_scope.dart:114 noteWorkspace`）、审批规则分键（`:64`）、检查点目录（`:385`）、备份清单、工作台持久化、安全边界本身。现在改只动"对外契约"那一层，等发布 API 落定再改要动双端。

## 6. 待验清单（这些不写进结论）

1. 两个工作区存在同名相对路径时，全局 `plan_space.json` 里的记录是否串（§2 后果 2）。
2. `planMockSeed()` 在 `plan_space.json` 已存在时是否还会掺进新记录（`open()` 的 `fallback: seed` 语义只在看不到文件/解析失败时生效，需实测已存在文档时的行为）。
3. 路径 2 的 md↔BlockNote 映射对**信封块**（`<!-- plan:{json} -->`）与 table(RxC) 能保住多少。
4. 发布后关闭分享，harness 侧的本地痕迹是否还提示"这篇已发出"（对面有 `disabled`/`expired` 状态，本侧目前没有任何"已发布"字段）。
5. 崩溃**已经在归档**（`lib/state/crash_archive.dart`、`lib/main.dart:74` 挂 `FlutterError.onError`、`app_providers.dart:84` 供 `CrashArchive` 与 `crashArchiveNonEmptyProvider`）——但"一键带走诊断"那一格有没有，我只证明了它有读者，没证明用户能把字节递出来。

## 8. 三个方向，我押一个

- **A「同一个文件夹的双面工作台」**：主叙事=§3 那句话；发布是出口；第一批用户=**既写代码也写计划的人**（工程师 / 独立开发者 / 技术型创作者）。解决机会 1、2、3、4。最高风险假设：这批人存在且愿意为此付费（DQ1/DQ6）。
- **B「企划星的桌面创作端」**：harness 变成企划星的本地优先客户端，人群换成大学生/创作者。解决机会 3、7。代价：要先修对象库归属、要接块模型转换、而这批人**不需要 agent**。最高风险假设：企划星的人群会装一个桌面 agent。
- **C「纯 agent 工作台，发布推后」**：只解决 1、4、5。代价：把已经投入的服务端与外循环变成沉没成本，形态②退化成"卖额度"。

**押 A。** 三条理由：① 只有 A 用上了本仓库唯一无法被抄的结构事实（agent 与企划读写同一批 `.md`）；② B 要求产品去服务一个对本产品核心能力无需求的人群，还要付两块内容模型转换的成本；③ A 与 B 的服务端需求是**同构的**（账号 + 分享 + 快照），所以选 A 不浪费已经投入的东西，而选 B 会浪费已经写的代理面与工具环。
但 A 的第一批用户**不能**从 B 的池子里找——这是大纲 §3 分池的全部理由。

## 9. 关键假设与最便宜的测试（一句话版）

**Critical**：除作者外，有人愿意让 agent 进自己的文件夹干活，并且把产出发出去。
**最便宜的测试**：不写一行新代码——用今天的构建，找 A 池 5 人 + B 池 5 人，各做一次 §大纲 4.1 的十分钟任务（用自己真实文件夹），只看三件事：他选了哪个目录、他读没读审批、他发出去以后说要给谁。

## 10. 三个锚点：已定案（详表见 `outline` §10、`bench` §7）

1. ✅ **发布单位 = 一个企划（= 一个工作区 = 一个站点）**，参照 hello-algo；不是单篇 `.md`。
2. ✅ **人群 = A 池，重定义为「写代码也写东西的人」**（开源维护者 / 技术作者 / 讲师 / 写方案的工程师）；企划星原定位的「大学生社团协作」降级——那是要协同编辑的人群，而我们不做协同编辑。
3. ✅ **`plan_space.json` 必须 per-workspace**——不是偏好，是①的推论：全局一份对象库无法界定「这个企划」的边界，发布时会串项目。**它是发布功能的第一前置，且目前没有任何 ADR 覆盖**（已登记进 `docs/debt-register.md` 观察表）。

**新留一个待验证的锚点④：定价与计费单位。** 外部实扫给的是 $8–10/站/月（Obsidian Publish）、$10/月（Copilot Pro）、$450/月（Mintlify Pro），而企划星押 3 元/7 元**按容量**——差一个数量级且轴不对（`bench` §5）。这一格要用一手价带数据拍，不能由我或竞品代码替我们决定。

## 11. 负结果记录（查了，不是缺陷）

我怀疑过"`settings.json` 的迁移重写会回表明文密钥"（`lib/state/settings_store.dart:61` 用的是 `value.toJson()`，而 `save()`/`resetToDefaults()` 用的是 `toJsonWithoutSecrets()`）。**查证为不成立**：`_v1ToV2` 在 `fromJson` 之前就把 `model.apiKey` 置空（`lib/model/app_settings_migration.dart:54`），内存里的 key 由 secret store 单独回灌（`settings_store.dart:70-75`），并且 `test/settings_hardening_test.dart:73-87` 是**读盘上字节**断言 `apiKey == ''` 的，还断言了 `.corrupt-<stamp>` 隔离保留原字节（`:91-101`）。
留一条防御深度的观察（非现行缺陷）：同一个写盘动作有两个序列化调用点，`:61` 之所以安全**依赖"迁移记得置空"**这个前提，而不是依赖写盘调用点收敛。加一条未来字段而忘记置空时，这行就会写出密钥。
