## 1. 侧栏的历史（ADR-0039）

| # | 步骤 | 应当看到 | 已由测试证过 |
| --- | --- | --- | --- |
| 1.1 | 打开两个不同文件夹各起 2–3 次会话，回到侧栏 | 一个文件夹一个组头，当前工作区那组排第一；组头是 `文件夹字形 + 名字`，会话行缩进一级 | `workspace_history_test`「one folder per header」「the folder the user is in leads」（**注意**：这台机器现在只有一个文件夹有历史，所以走查前要另开一个文件夹起一轮）|
| 1.2 | 亮/暗两档各看一次组头与行 | 组头底色与行底色不同档；选中行是整条圆角高亮，hover 只是加深一档，两者可分辨 | `workspace_history_test`「selected and hovered are two different washes on a row」——读的是**画出来的** `BoxDecoration.color`（亮档；反向验过：把选中令牌换成 hover 令牌即红，量到 `0.10` 对 `0.06`）。**只剩暗档那一圈是眼睛的活** |
| 1.3 | 点组头折叠，再点展开（整列的全折/全放是节头那枚钮，见 1.12） | 折叠只留表头不建行；整列仍可滚动，页脚钉在底部；**放大字号时列表不会被挤到 0 高** | `a folded group keeps its header and builds no rows`、侧栏放大文本两档 |
| 1.4 | 右键任意一行 | 六项：置顶/取消置顶、重命名、复制会话 id、复制工作区路径、在文件管理器中显示、删除 | `a conversation right-click can pin, rename and delete` |
| 1.5 | 置顶一条 → 重启应用 | 它仍在组内最前；相对时间从 `刚刚` 依次变 `59分`/`23天` | `a pinned conversation sits above a newer one`、`relative_time_test` 四档边界 |
| 1.6 | 删除一条 | 行消失、弹一条"已从列表移除该会话"；**盘上快照还在**（`<support>/sessions/…` 未被动过），重启后仍不在列表里 | `deleting a row leaves the snapshot listing alone` |
| 1.7 | 组头 `⋮` 四格逐一点 | 显示文件树 → 右栏开出该文件夹的树；复制工作区路径 → 粘出来是那个绝对路径；在文件管理器中显示 → Finder 真的打开；从列表中移除 → 只少这一组，会话还在 | 前三格由 `the group menu offers the tree, the path, the reveal and the removal` 守住（剪贴板读的是值本身）；**Finder 真打开只能你看** |
| 1.8 | 老会话（这次改动之前建的） | 落在最末一档「未归属」，不丢、不报错 | `a session with no folder lands in the unassigned bucket`。**本机实况已核对**：`~/Library/Application Support/com.stow.agentHarness/sessions/global/.pointers` 下 `.pointers` 有 **2** 个文件（=两条会话），而 `global/` 有 **7** 份快照——多出来的是同一批会话的快照链（新的那份带 `parentId` 指向上一份），`listSessions` **按指针列**，所以它们不该变成行，而侧车 `sessions.json` 还不存在——`listSessions` 从不填 `workspaceRoot`（`agent_runtime.dart:1364`），归属只在**新会话第一次落盘**时由 `AppScope.onSessionPersisted` → `noteWorkspace` 记下（`app_scope.dart:94`）。所以这台机器上屏幕上应当正好是 **2 行**（指针数），且这两条**全部**出现在「未归属」——看到 7 行、或看到它们被分到某个文件夹组里，才是问题 |
| 1.9 | 侧栏收起成 rail，再展开 | 收起时 rail 上没有一个字；展开后分组原样回来（淡入未 settle 时点在空气上——测试里踩过，所以真机请慢一点） | `both forms carry a working collapse control` |
| 1.10 | macOS 系统设置里把文字调大（四档各一次） | 组头、行、时间列都不被裁；整列还能滚到最后一行 | 两档（1.8x/2.2x）机器量过；**四档真机没量过** |

| 1.11 | 组头那枚 `+`：在**不是当前**的那个文件夹组上按它 | 应用换到那个文件夹并在其中起一次新会话（`adoptRecent` + `newSession`）；折叠/展开组**不会**换工作区（这是与上游的刻意分歧，理由在 ADR-0039 的追记第 2 条）。**这台机器现在只有一个文件夹有数据**，所以要走通得先随便再开一个文件夹起一轮 | 侧栏→回调这一截有守卫（`a folder group's + starts a conversation in that folder, 未归属 has none`，两半都反向验过）；**"换文件夹之后 agent 真能读那个目录、工作台也跟着换对"是 `AppScope.setWorkspace` 那一跳，只有真机能看** |

| 1.12 | 节头右侧那枚新图标（`⌄`/`⌃` 形状的两条横线）：全展开时按一次，再按一次 | 第一下把所有文件夹一起折起，图标与 tooltip 同时改口说「展开全部」；再按一次全部展开。**它说的必须是列表此刻的样子**——如果列表已全折起而它仍说「全部收起」，那就是又一枚假开关 | `the head glyph folds every group, then reads as unfold`（反向验过：把状态判断钉成常量即红）；**只剩"这枚图形认不认得出来是收起/展开"这一眼**（上游用 Minimize2/Maximize2，这里用同名 Lucide 字形） |

## 2B. 文件树里的变更（ADR-0043）

| # | 步骤 | 应当看到 | 已由测试证过 |
| --- | --- | --- | --- |
| 2B.1 | 打开一个有 git 的工作区，右栏文件树里让某个已跟踪文件脏起来 | 那一行右端一枚字母（`M`），与 git 面板同一文件上是**同一个字母**；干净文件一个字母都没有 | `a dirty file wears its letter and the header can show only those`（**反向验过**：徽标写死 `null` 即红在 `Found 0 widgets with text "M"`） |
| 2B.2 | 让脏文件埋在一个目录里，看那个目录行 | 目录行有一枚品牌色小点，一路向上都有；点与字母同时只会出现一个（文件读字母，目录读点） | 同一棵守卫（`src` 那行）；**"一眼能不能看出哪棵子树脏"是观感判断**，6px 的点不随字号长大（它是装饰不是文字，与 `Icon(size:)` 同律） |
| 2B.3 | 看头部那枚漏斗开关：关→开→关 | 只在**有变更时**才出现；开着时树只列变更文件与到达它们所需的祖先目录，且都自动展开；关掉立刻回到普通树（展开状态不丢） | 同上一条（开了之后断 `notes.md` 消失、`main.dart` 与 `src` 留下）；非 repo 目录由另一棵守住"既无字母也无开关" |
| 2B.4 | 开着开关但一个变更都没有（例如刚提交完） | 树是空的并说"这个文件夹里没有变更"，**不是**退回显示整棵树 | 空态那枚 `switch` 三分支；这条只被代码路径证过，真机请顺手看一眼 |
| 2B.5 | 在 git 面板 stage 一个文件 | 面板里那行进了"已暂存"，**同时**树里那行的字母变掉（同一份读数的两个读者） | `git_status_store_test`「an action invalidates, so the next reader sees the tree as it is now」证 store 层；两棵树**同时**变是眼睛的活 |
| 2B.6 | 让 agent 写一个文件（`write` 工具） | 树重列之后，新建的文件带 `?` 字母、它的目录带点——不需要你按刷新 | `_onFsRevision` 那条路径（`fsRevision` 抬 → `invalidate` + 再读）；**字母与"agent 刚写的那个文件"对得上没对上要看** |
| 2B.7 | 大仓（几万文件）第一次打开树 | 本机量过：**30,000 文件 / 1,500 处变更时 `git status` 是 41–42 ms**（5,000 文件是 15–22 ms，含进程启动，索引热的情况下）。所以正常机器上这一下不该被感知为停顿 | 数字是本机一次性仓库量的（测完即删），**只剩两样量不到**：索引冷时的那一发（很久没跑 git 的仓库），以及仓库在网络盘/外接盘上 |
| 2B.8 | **通过符号链接**选中一个文件夹当工作区（例如 `~/link-to-repo` 指向真仓库），打开树 | 徽标与目录点照样出现。这一格是修出来的：git 报解析过的顶层，而行是用户选中的拼法，两者不同时旧代码会**静默不画**（看起来像没这功能） | 前提与拼法都已用**真 git + 真目录**量过（`test/git_status_real_test.dart`：从 `/link` 问 `rev-parse --show-toplevel` 答 `/private/.../real`，且 `changedPaths` 的每个键都落在真的列表里；反向验过：退回直接拼在 git 顶层即红）。**只剩"你选的那条链接是否真的指向同一仓库"这一眼** |
| 2B.9 | 亮/暗两档、放大字号两档各看一次树 | 字母（11px 页边注）不被裁、行不横向溢；开关那枚 20px 座位在放大后仍能按 | `no tab body spills or cuts a label (1.8x / 2.2x)` 现在**把字母建在树里**再量（此前那两档走查用的是"非仓库"缓存，字母根本没进树——所以这一格今天才真正量到）；**淡不淡（`labelTertiary`）是眼睛的活** |

## 4. 还没做、等你点的候选（都带判据，不是待修 bug）

- **要不要一格"把这行归到当前工作区"**：本机核对过，那两条老会话在这台机器上**会全部**落在「未归属」，
  因为归属只在会话第一次落盘那一刻记下（之后换工作区不再改，这是 ADR-0039 的决策），而快照里没有可回溯的字段。
  上游没有这格（它的每条 task 建出来就带 `workspacePath`），所以这不是"漏移植"而是一件**新功能**：
  它等于让用户手写一条本来由系统记下的事实。要就说要，我按 ADR 流程立一条再动；不要就维持现状。
- **对话流的"全部展开/收起工具卡"与卡内搜索**：上游有（`ModelTrajectoryPane` 头部那排），
  但它那棵的正文要读服务端持久化的 transcript 目录，我们只有一半可搬。要哪一半请点一下。
- **窄窗胶囊的三条出口**（最小窗口宽 / 改吃 `constraints` / 接受为文档化退化）：仍无人拍板，
  所以窄窗守卫只跑到 1.8x。
- **树内重命名 / 新建文件 / 新建文件夹**：上游 `workspace-file-tree/` 里 grep `rename|newFile|createFolder|mkdir` 命中 0，
  它自己没接——要做是**新功能**（要写盘、要审批、要 i18n），不是"移植漏了"。
